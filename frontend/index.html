03 / Migration roadmap

Dependency-ordered waves — Foundation, Platform, Edge.

Kahn topological ordering

Call-site dependencies are sorted topologically, so a library is never scheduled before whatever it depends on. This is what prevents impossible migration timelines.

07 / CLI guide

The whole pipeline from a terminal, with no server running.

Python 3.10+ · MIT

The CLI is a first-class entry point, not a wrapper around the web UI. It registers as astra from the app.cli:main entry point, and every command runs entirely on the host — no licence check, no telemetry, no egress. This is the path used on air-gapped machines.

Install
# Python 3.10 or newer
pip install -r requirements.txt
pip install -e .            → registers the astra command
astra version              → confirms the install

# optional dev extras: pytest, httpx, black, ruff
pip install -e ".[dev]"
Command reference

Seven commands.

Generated scan ids are passed between them
CommandWhat it doesFlags
astra scan <path or archive> Runs static discovery across source, manifests, TLS/SSH configs, X.509 certificates and Dockerfiles, then reports honest coverage. Use table for a readable summary or json for machine consumption. --format table|json
--output <file>
astra show <scan-id> Prints the scan record: target, timestamp, coverage fraction, clean-state label and the SHA-256 Cryptographic DNA hash. —
astra risk <scan-id> Re-evaluates the Mosca inequality against a new scenario without rescanning. Prints per-algorithm risk score, urgency tier and slack. --horizon <years>
--shelf-life <years>
--migration <years>
astra export <scan-id> Writes the CycloneDX 1.6 CBOM projection to disk, ready for any SBOM consumer. --output <file>
astra validate <scan-id> Checks the emitted CBOM against the CycloneDX 1.6 schema and reports the component count. This is the step that backs the conformance claim. —
astra serve Starts the FastAPI service and this dashboard. Interactive API documentation lands at /docs. --host <addr>
--port <port>
astra version Prints the installed version so a run can be traced to a build. —

Behaviour worth knowing

Four things the CLI will not do.

Guarantees, not features
BehaviourWhy it matters
Never reports a false "safe" A repository with no cryptography in the supported scope is labelled NO_FINDINGS_IN_SUPPORTED_SCOPE next to a coverage caveat — never as clean or safe.
Never executes the target Uploaded code is parsed, not run. No installs, no imports, no evaluation of scanned content.
Never returns a bare percentage Coverage is always the fraction N_assessed / N_total, so an unsupported file format shows up as a blind spot rather than as coverage.
Never leaks private key material Detected key material is redacted to [REDACTED_PRIVATE_KEY_MATERIAL] before it reaches any report or export.

One scope note: direct astra scan runs against a directory are the path that reaches static binary headers (ELF, PE/COFF, Mach-O). Archive uploads through the web intake filter executables, so use the CLI when binaries are in scope.
