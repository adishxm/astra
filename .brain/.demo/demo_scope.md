# ECDAT synthetic demo plan (planning only)

## Purpose
Demonstrate the research-backed value proposition without NTRO data, production code, live network authority, or external AI: evidence-linked finding → confidence/coverage explanation → user context → transparent migration priority → sanitized export.

## Suggested scenario
Prepare a small authorized synthetic repository archive with (a) a vulnerable public-key use in a representative source file, (b) a modern algorithm reference, (c) a dependency manifest, (d) a sample certificate/config fixture, (e) a misleading non-cryptographic “key” string, and (f) one unsupported fixture. Ground truth is held separately from the scan input. Use only public/synthetic material and never private key bytes.

## Demo sequence
1. Show the explicit supported format and safe-upload boundary.
2. Start the scan and show status; include one unsupported/partial event in the report.
3. Open one finding and trace to sanitized path/line/hash, rule version and evidence state.
4. Show a duplicate or ambiguous observation without deleting its provenance.
5. Add illustrative data lifetime and criticality; change one scenario assumption and inspect the queue explanation.
6. Export a version-labelled CBOM-style file and human-readable summary; show coverage and limitations.
7. Compare only with a declared baseline and show actual measured results when the future implementation has run them.

## Rehearsal gates
- Synthetic-only dataset and checksum/version recorded.
- No uploaded code is executed; no endpoint or service is contacted.
- The assumption slider affects priority only through declared factors.
- No “all crypto found,” “quantum-safe,” or unsupported accuracy claim.
- Fallback: precomputed sanitized output may be shown only clearly marked as a recorded fixture result, not as a live scan.

No demo assets were included in the source archive, so this file is an instruction/plan, not a generated application asset.
